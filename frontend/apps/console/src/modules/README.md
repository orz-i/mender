# 前端模块

按用户任务组织模块，采用 domain / application / infrastructure / presentation。`service-status` 提供真实健康请求；`execution` 提供 Run Explorer；`workspace-access` 使用 HttpOnly OIDC browser session 获取用户和成员关系；`connection-access` 管理安全 Connection 投影与 reviewed OAuth；`catalog-management` 管理 Workspace-scoped ToolVersion/Toolset draft，并消费服务端 preflight、PolicyDecision 与 publication approval 状态，遵循 preflight → server policy → submit-for-review → approved → publish；`tool-launch` 消费服务端过滤后的 launch options，先请求 server-owned execution-risk decision；需要 Human confirmation 时显式确认 exact arguments hash，再通过绑定相同 hash 的短时 StartRun delegation 受理 Run；`usage-observability` 只读展示 Commerce quota 的 Budget/Usage 安全投影。Provider endpoint、scope、provider credential 和 delegated token 都不会由 domain 持有；敏感 token 仅作为 application 层短时工作流数据保存在当前页面内存。CSRF cookie 只在 infrastructure 读取并回显给状态变更请求。不预建通用 features 包。

模块公开入口为 index.ts。app 负责装配；领域与应用层保持纯 TypeScript，不导入 React、Router、Query 或 API DTO。Catalog 页面不会从 side-effect/idempotency、Membership、Connection、Budget 或 Pricing 自行计算风险、allow/deny、审核/发布资格；PolicyDecision、stale revision approval 与 publish postcondition 全由服务端给出。Publish 仍由数据库事务重校验策略/preflight 并消费 approval。Tool Launch 同样不根据 Workspace role、side-effect 或 idempotency 在浏览器推断 run:create 或 execution risk；只消费服务端 decision，并使用服务端返回的 arguments SHA-256 绑定 confirmation/delegation。Run Explorer 从 HttpOnly OIDC session 显式申请短时 Run delegation，token 只保存在页面内存，不能进入 URL、Query Key、localStorage 或 sessionStorage；OIDC Cookie 本身不直接访问 Run API，最终授权、状态与取消裁决始终来自后端。
