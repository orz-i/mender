# 原 S4-17：受控环境发布、恢复与对账操作

本手册使用已实现的服务端权限与S4工作台，不提供生产密钥、环境地址或虚构值班人。生产值班表、告警接收地址、备份存储及可信签名公钥仍需负责人配置与验收。

## 发布和回退

在 Console `/publisher` 提交已测试的不可变版本，由不同的审核人在 Admin `/release-management` 读取并核对精确版本后批准。创建发布计划、固定cohort灰度，再按已批准动作晋级。普通回退切换后续调用的绑定，不修改既有Run快照；应急禁用使用原危险操作审批，不允许由本地CLI或界面布尔值越权。

发布前对全部最终制品执行 `pnpm release:artifact verify SIGNED_ENVELOPE TRUSTED_PUBLIC_KEY`，并运行 `pnpm check:dependencies`。公钥必须来自独立可信配置；不读取制品自带的任意公钥作为信任锚。发布表单仍验证manifest和权限，不把离线签名当作审批替代。真正生产部署流水线应强制连接验证步骤；本轮没有远端部署操作。

## 停止扩量、异常和财务对账

发现授权越界、账本差异、秘密泄漏、意外副作用时，暂停相关新执行和发布，不删除原Run或账本。Admin `/platform-operations` 用明确原因冻结工作区、隔离Provider并登记事故；必要时走精确目标审批后禁用版本。支持人员通过 `/support-approvals` 申请有时限JIT，只读查询，不授予永久租户成员权限。

Admin `/billing` 读取账本汇总、待对账与sandbox意图状态。未知上游结果保持待确认，不自动释放或重投付费操作；退款／调账必须由另一个主体审核并生成补充分录，不改历史金额。支付跳转或模拟回调不是生产到账证明。操作和告警的实际责任人须在值班表登记，本地测试不能代替该安排。

## 真实本地备份恢复演练

命令：`pnpm test:s4:recovery`。先构建前端，再由既有Docker安全编排创建随机标识、受限资源、仅loopback的临时PostgreSQL容器。恢复测试只接受编排器的随机容器名/nonce，核验所有权标签、发布端口和实际临时数据库名；不能把命令指向开发持久库或生产库。

在完整S4数据场景后，对原临时库执行pg_dump(custom)，恢复到**另一个临时库**；对Run、受理、Job、预算、账本journal/entry、支付意图和迁移校验表逐项比较行数与排序事实摘要，验证完整迁移hash。源库不做回档。目标库和备份都仅在自有临时容器中，结束删除目标库及容器。

演练为受控数据恢复，使用`--no-owner --no-acl`，因此不认证真实环境角色ACL、跨集群权限、主密钥恢复、外部对象存储或生产RPO/RTO。真实恢复时应先停止执行，恢复和验证所有者/运行角色、凭据与对象引用，然后隔离恢复窗口内的未知外部任务，逐项对账后再允许Worker，不能全量重放。

## 本轮证据和剩余批准

实际命令回执由 `scripts/record-s4-verification.mjs` 捕获UTC时间、退出码、日志和源码指纹，且拒绝测试期间源码漂移。它不生成批准记录。G4汇总保留生产/商业/远端强制合并门禁等待确认；该手册不是自动上线授权。
