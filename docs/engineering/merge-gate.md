# 主干检查与远端合并门禁

## 当前仓库可控制的部分

`.github/workflows/ci.yml` 的 `check` 作业执行固定工具链安装、`pnpm check` 与独立真实 PostgreSQL 集成。状态一致性检查通过 `pnpm check` 接入，不取代现有业务测试，也不放宽数据库失败处理。

CI 配置存在、某次运行 success、源码检查器输出 PASS，都不能证明 GitHub 已要求通过检查才能合并。是否启用远端规则是另一控制面，本轮仅修改本地仓库，没有更改远端权限／规则集，也未读取实时规则，因此在主台账保留 `remote-merge-protection: not-verified`。

## 管理员需要完成的放行条件

为 `main` 设置受审的 PR／必需状态检查规则，选择实际报告的 `check` 作业（同时包含综合检查和真实数据库步骤），核对管理员／机器人绕过权限；不得只要求一个校验证据 JSON 的轻量脚本。具体允许谁绕过、是否要求人工复核，由仓库负责人确认，不在本轮自我授权。

保存仓库／分支、规则标识、适用对象、所需检查、核验时间及操作人；用一次失败检查的 PR 验证正常合并路径确实受阻，再更新外部条件。远端核验记录应独立于普通测试文件；不要把本说明或源码 hash 当远端生效证据。

本次不执行 push、部署、分支保护修改或危险数据库命令。需要外部管理权限的纠偏仍是未关闭条件，不因本地新会话完成而写成已解决。
