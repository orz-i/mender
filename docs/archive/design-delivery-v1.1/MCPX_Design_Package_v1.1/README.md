## 本轮关键约束

前端在仓库根维护单一 pnpm workspace 与单一锁文件，应用和共享包采用 workspace 依赖；Node 与 pnpm 精确版本在 G0 核验后锁定。Go 保留独立的 go.mod／go.sum，不归 pnpm 管理。本包没有生成未经实际安装验证的 pnpm-lock.yaml。

后端先按业务限界上下文拆分，再在每个上下文内组织 `domain / application / adapters / public`。源码依赖向内；消费方声明端口，外层实现，Composition Root 显式装配。Gin、SQL、SDK、HTTP DTO 和数据库事务类型不能泄露到领域层。前端按用户任务组织领域模块，不强制照搬全部后端上下文。

8 个上下文是 G0 待冻结的候选边界，不等于 8 个微服务。Provider 主记录归 supply，Tool／ToolVersion 归 catalog，价格和资金归 commerce。表、迁移和事件合同必须有唯一所有者。

付费调用受理仍要求 Run、预算预留、任务和 Outbox 原子提交。ADR-020 将 execution／commerce 同库协调明确为受控例外：通过专用事务端口与事务作用域服务装配实现，禁止协调器绕过领域所有者直接写表。它不允许其他跨上下文事务自动获得豁免。

先读专项规范 G00、G02、G04、G06、G07，确认工程规则；再核对架构文档 A03、A13、A14、A17。实施负责人结合计划 B00–B04、Excel 的 WBS／DDD上下文／工程治理表，确认 G0–G1 的责任人与证据。

治理表追踪规则，WBS 追踪执行人日；两者不能重复累计工作量。规则、实施任务和测试编号已关联，但 CI 接线、负向 fixture 和真实测试尚待团队实现。

## 排期与容量口径

20 周从正式启动周 W1 起算，不以文档日期作为开工承诺。原配置为 2 名后端、1 名前端、1 名测试，以及 0.5 名 SRE／安全支持和 0.5 名产品／项目负责人。按每周 5 天、80% 有效投入计算，容量为 400 人日。

本轮保留 92 个任务及 261.25 基础人日，含 15% 缓冲约 300.44 人日，**仅作为 G0 待重新校准的原估算**。20 个任务新增或强化了工程治理验收；任务数未增加不代表实施成本不变。未提供已有代码，未估算代码迁移；已有项目、团队学习和工具接入工作应在 G0 单独拆分并重算负载。

S0 W1–W2：范围与高风险验证；S1 W3–W5：工程与租户底座；S2 W6–W9：HTTP Alpha；S3 W10–W13：MCP／Agent 集成内测；S4 W14–W17：发布治理与商业准备；S5 W18–W20：加固与受控 Beta。S6 隔离运行时独立准入、单独估算。

## 台账使用

项目总览的蓝色输入用于调整周数、工作日、有效投入、风险缓冲、当前周与角色 FTE。WBS 的 I／Q 列为公式；进度使用百分比。阶段甘特按本版 20 周展示，变更周期后须同步维护阶段窗口和图示列。

新增任务应扩展表格和公式；原汇总范围预留至第 505 行。任务初始为“未开始”、测试为“未执行”、工程规则为“待评审”或“未实施”；不得用文档生成替代实施证据。ADR-017／018／019 的“用户约束”表示方法已确认，不是团队评审签字；ADR-020 仍须正式评审。

Word、PDF、Markdown、JSON 与 Excel 是同一版本的静态快照，不会实时双向同步。调整基线后应同步相关交付物、保留变更记录，并重新发布。

## 合同、来源与验证边界

在 `contracts/` 运行 `python validate_contracts.py`，需要 Python 3、PyYAML 与 jsonschema。它只验证合同结构、Schema、引用、参数和摘要，不替代完整 OpenAPI 检验、MCP 一致性、安全、并发、支付或真实供应商集成测试。

架构 A18 收录 35 项官方／一手来源。S01–S25 保留 v1.0 的资料记录，本轮新增核验 S26–S35；可变文档与精确依赖版本在 G0 再核验。本包不声称已测试 Monid 的私有后台，也不把方法文档当作已完成代码的证据。

示例不含真实凭据；工程模板未接入真实仓库。交付包不包含字体、渲染中间页或完整业务应用。所有性能、兼容性、恢复和上线目标均待真实环境验证。
